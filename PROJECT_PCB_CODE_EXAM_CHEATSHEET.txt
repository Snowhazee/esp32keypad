ส่วนที่ 1: ภาพรวมระบบทั้งระบบ (System Architecture Overview)
================================================================================

โปรเจกต์นี้คือ "Custom Macro Keypad & Multimedia Rotary Controller"
ขับเคลื่อนด้วยไมโครคอนโทรลเลอร์ ESP32-S3 (บอร์ด ESP32-S3 DevKit 44 พิน)

1.1 องค์ประกอบของระบบ:
1) Core MCU: ESP32-S3 (Dual-Core Xtensa LX7 @ 240 MHz, 8MB Flash, 2MB PSRAM)
   - จุดเด่น: มีวงจร Native USB OTG ในตัว สามารถทำตัวเป็น USB HID Keyboard แท้ๆ ได้
2) Mechanical Switches (3 ปุ่ม):
   - SW_1 (K1) -> GPIO 4
   - SW_2 (K2) -> GPIO 5
   - SW_3 (K3) -> GPIO 6
3) Rotary Encoder with Push Button (Knob EC11):
   - หมุน Phase A -> GPIO 7
   - หมุน Phase B -> GPIO 8
   - ปุ่มกด Switch -> GPIO 9
4) Addressable RGB LEDs (WS2812B / NeoPixel จำนวน 3 หลอด):
   - Data In (DIN) -> GPIO 10 (ต่อแบบ Daisy Chain ขนานไฟเลี้ยง)
5) วงจรกรองไฟ (Power Filtering & Decoupling Circuit):
   - ตัวเก็บประจุ C1, C3, C4, C_Electrolytic และตัวต้านทาน R1
6) ซอฟต์แวร์บนคอมพิวเตอร์ (Windows Companion Apps):
   - KeypadConfigurator (PowerShell GUI สำหรับแมปปุ่มและบันทึกลง Flash)
   - KnobMacro (โปรแกรมดักรับ Serial ส่งปุ่ม Windows ผ่าน Win32 API)

ส่วนที่ 2: เจาะลึกแผ่นวงจร PCB (PCB Layout Analysis จากรูปจริง)
================================================================================

2.1 การแบ่ง Layer ของแผ่น PCB:
- สีแดง (Red Traces) = ด้านบน (Top Layer)
- สีน้ำเงิน (Blue Traces) = ด้านล่าง (Bottom Layer)
- เส้นสีเหลือง (Yellow Silk) = Silkscreen บอกขอบเขตและตำแหน่งอุปกรณ์

2.2 การเดินสายของแต่ละอุปกรณ์บน PCB:

[A] สวิตช์ Mechanical (SW_1, SW_2, SW_3):
- ทำงานแบบ Active-LOW (กดแล้วต่อลงกราวด์)
- SW_1: ขา 2 ต่อเส้นสีน้ำเงินเข้า GPIO 4 / ขา 1 คือ GND
- SW_2: ขา 2 ต่อเส้นสีแดงเข้า GPIO 5 / ขา 1 คือ GND
- SW_3: ขา 2 ต่อเส้นสีน้ำเงินเข้า GPIO 6 / ขา 1 คือ GND

[B] สวิตช์หมุน (KNOB - Rotary Encoder EC11):
- ด้านล่าง (3 ขา):
  * ขาซ้าย: ต่อเส้นสีน้ำเงินเข้า GPIO 7 (Encoder Phase A)
  * ขาขวา: ต่อเส้นสีน้ำเงินเข้า GPIO 8 (Encoder Phase B)
  * ขากลาง: ขาร่วม (Common) สำหรับขั้วกราวด์ของการหมุน
- ด้านบน (2 ขา):
  * ขาขวา: ต่อเส้นสีน้ำเงินเข้า GPIO 9 (Push Switch)
  * ขาซ้าย: ต่อเส้นสีแดงเข้าขั้ว GND
- ด้านข้าง (MP, MP):
  * Mounting Pads สำหรับบัดกรีลงบอร์ดเพื่อความแข็งแรงเชิงกลเวลาหมุน/กด

[C] ไฟ RGB LED (LED1, LED2, LED3):
- เป็น Addressable LED (รุ่น WS2812B หรือเทียบเท่า):
  * สัญญาณข้อมูลเข้า (DIN) ของ LED1 มาจาก GPIO 10 (เส้นสีแดงด้านบน)
  * จากนั้น DOUT ของ LED1 วิ่งต่อไป DIN ของ LED2
  * และ DOUT ของ LED2 วิ่งต่อไป DIN ของ LED3 (การต่อแบบ Daisy Chain)
  * เส้นไฟ VIN+ และ GND วิ่งขนานเลี้ยงทุกหลอด

[D] วงจรภาคจ่ายไฟและกรองสัญญาณ (U1 Area / C1, C3, C4, Cap กระป๋อง):
- มีตัวเก็บประจุ Decoupling Capacitor (C1, C3, C4) เพื่อกรองสัญญาณรบกวนความถี่สูง (High Frequency Noise) ให้กับระบบไฟเลี้ยง
- มี Electrolytic Capacitor (ตัววงกลมมีขั้ว + -) ทำหน้าที่เป็น Bulk Capacitor สำรองพลังงาน ป้องกันแรงดันตกชั่วขณะเวลาหลอดไฟ LED ติดสว่างพร้อมกัน

ส่วนที่ 3: จุดวิกฤตและบั๊กบน PCB ที่ต้องระวัง (PCB Critical Points)
*** ส่วนนี้สำคัญมาก อาจารย์ภาคฮาร์ดแวร์ชอบจับผิด ***
================================================================================

หากดูจากภาพลายวงจร (PCB Layout) จะเห็นจุดน่าสงสัยทางฮาร์ดแวร์ 3 จุด:

1) ขากลางด้านล่างของ KNOB (Encoder Common Pin):
   - ในรูป ลายเส้นสีน้ำเงินวิ่งผ่านใต้ Knob ไปยัง GPIO 7 และ 8
   - แต่ "ขากลางด้านล่างของ Knob ไม่มีเส้นลายวงจรเชื่อมต่ออยู่เลย!"
   - การตอบอาจารย์:
     * ถ้าบอร์ดนี้มีการเทระนาบกราวด์ (Ground Copper Pour ทั้งแผ่น): ขากลางนี้จะเชื่อมกับกราวด์ผ่าน Thermal Relief Pad
     * แต่ถ้าแผ่นนี้ "ไม่ได้เทกราวด์ (Unpoured Copper)": ขากลางนี้จะลอย (Floating) ทำให้เมื่อหมุนลูกบิด ขา 7 และ 8 จะไม่มีทางแตะกราวด์ ส่งผลให้ "หมุน Knob แล้วไม่ติด 100%" (นี่คือสาเหตุที่แท้จริงทางฮาร์ดแวร์!)

2) ขา GND ของ SW_1 (ปุ่มแรกซ้ายมือ):
   - ในรูป เส้นสีแดงลากจาก LED3 วิ่งตรงไปเข้าขา GND ของ SW_2 และ SW_3 เลย
   - โดย "ไม่มีเส้นวิ่งเข้าไปที่ขา GND ของ SW_1"
   - การตอบอาจารย์: ให้สังเกตเช่นเดียวกันว่า หากไม่มี Ground Pour ขา GND ของ SW_1 จะลอย ทำให้กดปุ่ม K1 ไม่ติด เว้นแต่ว่าจะมี Ground Plane คลุมทั้งแผ่น

3) การเดินลายเส้นตัดกัน (Cross-over & Via):
   - มีการใช้ Layer แดง (Top) และน้ำเงิน (Bottom) เพื่อหลบไม่ให้เส้นสัญญาณลัดวงจรกัน เป็นการออกแบบ 2-Layer PCB มาตรฐาน

ส่วนที่ 4: เจาะลึกโครงสร้างเฟิร์มแวร์ (Firmware Code ใน src/main.cpp)
================================================================================

4.1 ระบบจัดการโปรไฟล์ (Profile Architecture):
- บอร์ดรองรับ 3 โปรไฟล์ (Profile 0, 1, 2)
- เก็บข้อมูลในโครงสร้าง `struct ProfileConfig`:
  * `buttonKeys[3]`: ปุ่มที่แมปไว้ของ K1, K2, K3
  * `clockwiseAction`: คำสั่งเมื่อหมุนตามเข็ม
  * `counterClockwiseAction`: คำสั่งเมื่อหมุนทวนเข็ม
  * `encoderPressKey`: คำสั่งเมื่อกดปุ่ม Knob
- ใช้ไลบรารี `Preferences.h` เก็บลง NVS Flash Memory โดยอัตโนมัติ

4.2 การอ่านปุ่มและการ Debounce (Non-blocking):
- ฟังก์ชัน `updateButton()` ใช้ค่าเวลา `millis()` ในการจับเวลา Debounce (20 ms)
- ไม่มีการใช้ `delay()` แม้แต่จุดเดียว ทำให้ระบบมีความไว (Latency ต่ำมาก) ตอบสนองทันที

4.3 การถอดรหัส Rotary Encoder (Gray Code State Machine):
- ฟังก์ชัน `updateEncoderRotation()`:
  * นำค่าสัญญาณจากขา 7 และ 8 มารวมกันเป็น 2 บิต `(digitalRead(A) << 1) | digitalRead(B)`
  * นำสถานะเก่า 2 บิต รวมกับสถานะใหม่ 2 บิต กลายเป็น Index 4 บิต (0-15)
  * วิ่งเข้าตาราง Lookup Table `kTransitions[]` เพื่อดูทิศทาง (+1 หรือ -1)
  * เมื่อสะสมการหมุนครบ 4 สเต็ป (`encoderDelta >= 4` หรือ `<= -4`) จะสั่งฟังก์ชัน `sendEncoderAction()`

4.4 การทำงานแบบ Dual USB (HID + CDC):
- เมื่อต่อผ่าน Native USB ของ ESP32-S3:
  * `keyboard.begin()`: เปิดโหมด USB HID Keyboard
  * `USB.begin()`: เปิดโหมด USB Composite Device
  * `Serial.begin(115200)`: ส่งข้อมูลผ่าน USB CDC Serial เพื่อคุยกับ GUI บนคอม

4.5 โปรโตคอลการสื่อสารผ่าน Serial (Serial Command Protocol):
- คอมพิวเตอร์ส่งคำสั่งมาแบบ Text จบด้วย Newline `\n`:
  * `GET`: บอร์ดตอบกลับค่า Configuration ปัจจุบัน `CFG|active|k1|k2|k3|cw|ccw|sw`
  * `SET|field|value`: ปรับเปลี่ยนค่าปุ่มในหน่วยความจำ
  * `PROFILE|index`: สลับโปรไฟล์การใช้งาน
  * `SAVE`: สั่งบันทึกลง Flash Memory NVS

ส่วนที่ 5: แนวทางการตอบคำถามอาจารย์แบบแยกหมวด (Q&A)
================================================================================

[ หมวดที่ 1: คำถามเกี่ยวกับวงจร & PCB ]

Q1: "อธิบายหน้าที่ของ C1, C3, C4 และตัวเก็บประจุตัวใหญ่ตรงกลางบอร์ดหน่อย?"
A1: "C1, C3, C4 คือ Decoupling Capacitors (มักเป็นเซรามิก 0.1 uF) วางใกล้ตำแหน่งไฟเลี้ยงเพื่อกรองสัญญาณรบกวนความถี่สูง (High Frequency Ripple) ไม่ให้กวนระบบประมวลผล
ส่วนตัวเก็บประจุทรงกระบอกที่มีขั้วคือ Electrolytic Bulk Capacitor ทำหน้าที่เป็นแหล่งสำรองพลังงานชั่วขณะเวลาหลอดไฟ RGB LED 3 ดวง หรือวงจร USB มีการดึงกระแสกระชาก ป้องกันแรงดันไฟตก (Voltage Sag) ครับ"

Q2: "บน PCB ใช้ตัวต้านทาน Pull-up ภายนอกไหม หรือใช้แบบไหน?"
A2: "ในวงจรนี้เราพึ่งพา Internal Pull-Up Resistor ภายในชิป ESP32-S3 ครับ มีค่าประมาณ 45 kΩ สวิตช์ทุกตัวและ Knob จึงต่อลงกราวด์ (GND) ทำงานแบบ Active-LOW แต่หากนำไปผลิตเป็นโปรดักต์ระดับอุตสาหกรรม ควรเพิ่มตัวต้านทาน Pull-up ภายนอกขนาด 4.7 kΩ ถึง 10 kΩ เพื่อความเสถียรต่อสัญญาณรบกวน EMI ครับ"

Q3: "ทำไมถึงต่อไฟ LED แบบ Daisy Chain (เส้นสีแดงด้านซ้าย)?"
A3: "ไฟ LED บนบอร์ดคือหลอดประเภท Addressable RGB (เช่น WS2812B) ซึ่งใช้การสื่อสารแบบ One-Wire Protocol ด้วยสัญญาณพัลส์ความถี่ 800 kHz ข้อดีคือใช้ขา GPIO เพียงขาเดียว (GPIO 10) แต่สามารถควบคุมสีและความสว่างของไฟ LED ทุกหลอดแยกจากกันได้อย่างอิสระ ผ่านการส่งข้อมูลต่อกันเป็นทอดๆ จาก DOUT ไปยัง DIN ครับ"

[ หมวดที่ 2: คำถามเกี่ยวกับ Rotary Knob ]

Q4: "ทำไม Rotary Encoder ถึงไม่ใช้ Analog Input อ่านค่าแบบ Potentiometer?"
A4: "Potentiometer เป็นตัวต้านทานปรับค่าได้ มีมุมหมุนจำกัดราว 270-300 องศา และให้ค่าเป็นแรงดันแอนะล็อกซึ่งมีปัญหาเรื่อง Noise และการสึกหรอของหน้าสัมผัส
ส่วน Rotary Encoder เป็นระบบ Digital Pulse หมุนได้ 360 องศาไม่รู้จบ ส่งสัญญาณเป็น Gray Code Quadrature 2 ช่องสัญญาณ มีความแม่นยำสูงกว่า และเหมาะมากกับการใช้ปรับเพิ่ม-ลดเสียงหรือการเลื่อนหน้าจอที่ต้องการความต่อเนื่องครับ"

Q5: "ถ้าหมุน Knob เร็วมากๆ แล้วมีปัญหาหลุดสเต็ป จะแก้ที่ Code หรือ Hardware อย่างไร?"
A5: "สามารถแก้ได้ 2 ทางครับ:
1. ด้าน Hardware: ใส่ฟิลเตอร์ RC Low-pass filter (10kΩ + 10nF) บน PCB เพื่อตัดสัญญาณ Contact Bounce
2. ด้าน Firmware: เปลี่ยนจากการ Polling ใน loop() ไปใช้ Hardware Interrupts หรือใช้โมดูลฮาร์ดแวร์ PCNT (Pulse Counter) ซึ่งเป็น Peripheral เฉพาะในชิป ESP32-S3 ที่สามารถนับสัญญาณ Quadrature ได้ในระดับวงจรฮาร์ดแวร์โดยตรงครับ"

[ หมวดที่ 3: คำถามเกี่ยวกับ Firmware & ระบบซอฟต์แวร์ ]

Q6: "ระบบจำค่าปุ่มกดได้อย่างไรเวลาถอดสาย USB ออกไปเสียบเครื่องอื่น?"
A6: "เราใช้ไลบรารี Preferences.h ของ ESP32 ซึ่งทำงานบน NVS (Non-Volatile Storage) ใน Flash Memory ครับ เมื่อผู้ใช้กดบันทึก ข้อมูลรหัสปุ่มของทั้ง 3 โปรไฟล์จะถูกเขียนลง Flash แบบถาวร เมื่อเปิดเครื่องขึ้นมาใหม่ ฟังก์ชัน loadProfiles() จะอ่านค่าเหล่านี้ขึ้นมาเก็บใน RAM ทันทีครับ"

Q7: "ทำไมบอร์ดนี้ถึงส่งปุ่มเข้าคอมพิวเตอร์ได้โดยไม่ต้องลงโปรแกรม Driver ใดๆ เพิ่มเติม?"
A7: "เพราะ ESP32-S3 มี USB Full-Speed OTG Peripheral ในตัว เฟิร์มแวร์จึงรันไลบรารี USBHIDKeyboard เพื่อประกาศตัวเป็น USB HID Standard Class (Human Interface Device) ซึ่งระบบปฏิบัติการอย่าง Windows, macOS หรือ Linux มีไดรเวอร์มาตรฐานในตัวอยู่แล้ว จึงสามารถ Plug-and-Play ได้ทันทีครับ"
