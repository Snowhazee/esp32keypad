1. วิเคราะห์สาเหตุ: ทำไม Knob ถึงไม่ติด?
================================================================================
จากที่ตรวจสอบโค้ดใน src/main.cpp และฮาร์ดแวร์ มี 4 สาเหตุหลัก:

1.1 ค่า Default ของการหมุนในโค้ดถูกตั้งเป็น "kNoAction" (ค่า 0)
    - ในโค้ด defaultProfile() กำหนดค่าเริ่มต้นของ clockwiseAction และ counterClockwiseAction เป็น 0
    - ฟังก์ชัน sendEncoderAction() มีเงื่อนไขว่า:
        if (action == kNoAction) { return; }
    - ทำให้เมื่อแฟลชเฟิร์มแวร์ลงบอร์ดใหม่ๆ หากยังไม่ได้เปิดโปรแกรม KeypadConfigurator เพื่อเลือก Action แล้วกด "Save to keypad" การหมุน Knob จะไม่มีการตอบสนองใดๆ และไม่มี Serial Debug ออกมาเลย

1.2 Logic การถอดรหัสและ Mechanical Contact Bounce
    - สวิตช์หมุนแบบ EC11 เป็นหน้าสัมผัสทางกล เวลากลไกหมุนจะเกิดการเด้งของสัญญาณ (Bounce)
    - ในโค้ด updateEncoderRotation() เดิม เมื่อเจอจังหวะ Bounce จะสั่ง `encoderDelta = 0;` ทันที
    - ทำให้ค่าสะสมตัวนับถูกล้างทิ้งตลอดเวลา หมุนแล้วไม่ถึงสเต็ป 4/ -4 ส่งผลให้หมุนแล้วค้างหรือไม่ขยับ

1.3 พอร์ต USB ที่เสียบใช้งาน (Native USB vs UART)
    - บอร์ด ESP32-S3 ส่วนใหญ่มี 2 พอร์ต Type-C:
      1) ช่อง "USB" (Native USB - GPIO 19/20): บอร์ดจะทำตัวเป็น HID Keyboard ส่งปุ่มเข้า Windows ได้โดยตรง
      2) ช่อง "UART/COM" (ผ่านชิปแปลง): ส่งได้เฉพาะข้อความ Serial เท่านั้น ต้องเปิดโปรแกรม Start-KnobMacro.cmd คอยดักอ่าน Serial แล้วส่งปุ่มแทน
    - หากเสียบช่อง UART แต่ไม่ได้เปิดแอป Macro หรือเปิด Serial Monitor ค้างไว้จนแอปเปิดพอร์ตไม่ได้ ปุ่ม Knob จะไม่ส่งผลอะไรในคอมพิวเตอร์

1.4 การต่อสายและ Pull-up Resistor
    - ขาที่ใช้: Pin A = GPIO 7, Pin B = GPIO 8, Push Switch = GPIO 9
    - ขากลาง (Common) ของ Encoder และขาหนึ่งของ Switch ต้องต่อลง GND
    - บอร์ดใช้ internal pull-up หากสายหลวมหรือขา Common ไม่ลง GND สัญญาณจะค้างเป็น 1 (HIGH) ตลอดเวลา

2. ไฟล์ทดสอบฮาร์ดแวร์ (Hardware Test File)
================================================================================
ได้สร้างไฟล์ทดสอบฮาร์ดแวร์ไว้ที่: test/test_hardware.cpp
วิธีใช้งาน:
1) ก๊อปปี้โค้ดใน test/test_hardware.cpp ไปวางใน src/main.cpp ชั่วคราว
2) Upload ลงบอร์ด ESP32-S3 แล้วเปิด Serial Monitor ที่ Baudrate 115200
3) ผลการทดสอบ:
   - หมุนขวา (CW) -> แสดงข้อความ [ROTARY] >> หมุนตามเข็ม (CW) พร้อมค่า Count เพิ่มขึ้น
   - หมุนซ้าย (CCW) -> แสดงข้อความ [ROTARY] << หมุนทวนเข็ม (CCW) พร้อมค่า Count ลดลง
   - กดปุ่ม Knob หรือ K1, K2, K3 -> แสดงสถานะ PRESSED (LOW) ทันที
   - มี Status Heartbeat รายงานระดับขา GPIO 7, 8, 9 ทุกๆ 3 วินาที

[ Slide 2: สถาปัตยกรรมระบบ (System Architecture) ]
--------------------------------------------------------------------------------
เนื้อหาในสไลด์:
• Core MCU: ESP32-S3 (Dual-core Xtensa LX7 240MHz, 8MB Flash, 2MB PSRAM)
• Input Interfaces:
  - 3x Mechanical Switches: GPIO 4 (K1), GPIO 5 (K2), GPIO 6 (K3)
  - 1x EC11 Rotary Encoder: GPIO 7 (Phase A), GPIO 8 (Phase B), GPIO 9 (Push Switch)
• Dual-Mode Communication:
  - Direct USB HID: บอร์ดทำตัวเป็น USB Keyboard แท้ๆ ไม่ต้องลง Driver
  - USB CDC (Serial): สื่อสารกับโปรแกรมตั้งค่าบน PC ด้วย Baudrate 115200

บทพูดพรีเซนต์:
"โครงสร้างระบบแบ่งออกเป็น 2 ส่วนหลัก คือ ภาคฮาร์ดแวร์ เราใช้ ESP32-S3 ควบคุมสวิตช์ mechanical 3 ตัว และตัว Rotary Encoder เพื่อหมุนปรับแต่งการทำงาน ส่วนภาคการสื่อสาร บอร์ดจะทำงานแบบ Dual-Mode คือเป็นทั้ง USB HID Keyboard ส่งคีย์ตรงเข้าเครื่อง และเป็น USB CDC Serial เพื่อรับคำสั่งตั้งค่าโปรไฟล์จากแอปพลิเคชันครับ"

--------------------------------------------------------------------------------
[ Slide 3: หลักการทำงานของ Rotary Encoder (Gray Code Quadrature) ]
--------------------------------------------------------------------------------
เนื้อหาในสไลด์:
• หลักการสร้างพัลส์แบบ Quadrature (Phase A และ B ต่างเฟสกัน 90 องศา)
• การวิเคราะห์ทิศทางการหมุน:
  - Phase A นำ Phase B -> หมุนตามเข็มนาฬิกา (Clockwise: CW)
  - Phase B นำ Phase A -> หมุนทวนเข็มนาฬิกา (Counter-Clockwise: CCW)
• State Transition Matrix:
  - ใช้ Lookup Table 4x4 ในการตรวจสอบการเปลี่ยนสถานะ (00 -> 01 -> 11 -> 10)
  - การกรองสัญญาณ Contact Bounce ของหน้าสัมผัสทางกล

บทพูดพรีเซนต์:
"หลักการของ Rotary Encoder คือการสร้างสัญญาณ Gray Code 2 ช่องสัญญาณที่เยื้องมุมกัน 90 องศา ระบบของเราใช้ State Transition Matrix ในการตรวจสอบลำดับการเปลี่ยนสถานะของพิน A และ B ทำให้ระบบแยกแยะได้อย่างแม่นยำว่าผู้ใช้กำลังหมุนตามเข็มหรือทวนเข็มนาฬิกา พร้อมมีระบบตัดสัญญาณรบกวนหรือ Bounce ทางกลครับ"

[ Slide 4: เฟิร์มแวร์และการจัดการหน่วยความจำ (Firmware & Storage) ]
--------------------------------------------------------------------------------
เนื้อหาในสไลด์:
• Non-Blocking Debounce:
  - ตรวจจับปุ่มกดด้วยการวัดเวลา millis() กำหนด Threshold 20ms
  - CPU ไม่ถูกบล็อก สามารถประมวลผลการหมุนได้อย่างต่อเนื่อง
• NVS (Non-Volatile Storage):
  - ใช้ไลบรารี Preferences.h บันทึกโปรไฟล์ลงใน Flash Memory
  - ปิดเครื่องหรือย้ายไปเสียบเครื่องอื่น การตั้งค่าไม่สูญหาย
• Serial Command Protocol:
  - GET: อ่านโปรไฟล์ปัจจุบัน
  - SET|field|key: ตั้งค่าปุ่มและทิศทางการหมุน
  - SAVE: บันทึกการตั้งค่าลง NVS

บทพูดพรีเซนต์:
"ในฝั่งเฟิร์มแวร์ เราออกแบบให้อ่านปุ่มแบบ Non-blocking โดยใช้ฟังก์ชัน millis() หน่วงเวลา 20ms จึงไม่ทำให้ระบบหยุดชะงัก และเรายังบันทึกการตั้งค่าปุ่มของทั้ง 3 โปรไฟล์ลงใน Flash Memory ผ่านระบบ NVS ทำให้เมื่อถอดปลั๊กไปเสียบคอมเครื่องอื่น คีย์แพดยังคงจำค่าเดิมได้โดยไม่ต้องเปิดแอปตั้งค่าใหม่ครับ"

[ Slide 5: ปัญหาที่พบในระหว่างการทดลองและการแก้ไข (Troubleshooting) ]

เนื้อหาในสไลด์:
• ปัญหาที่ 1: หมุน Knob แล้วไม่มีการตอบสนอง
  - สาเหตุ: ค่า Default ในเฟิร์มแวร์ตั้งไว้เป็น kNoAction (0) และเงื่อนไขตัดการส่งข้อมูล

  - การแก้ไข: ปรับปรุง State Transition Table และไม่ล้างตัวแปรเมื่อเจอ Invalid State
• ปัญหาที่ 3: ความแตกต่างของพอร์ต Native USB vs UART
  - การแก้ไข: สร้างสคริปต์สำรอง KnobMacro สำหรับส่งปุ่มผ่านทาง Serial ในกรณีที่ใช้พอร์ต UART

"ในระหว่างพัฒนา เราพบปัญหาว่า Knob ไม่ตอบสนอง ซึ่งมาจากการที่ค่าเริ่มต้นในโค้ดถูกตั้งเป็น NoAction และมีปัญหาเรื่องสัญญาณกระดอนของหน้าสัมผัส เราได้ทำการแก้ปัญหาโดยปรับปรุงอัลกอริทึม State Machine ให้มีความทนทานต่อสัญญาณรบกวน พร้อมเพิ่มระบบแจ้งเตือนทาง Serial เพื่อให้ตรวจสอบสถานะฮาร์ดแวร์ได้ง่ายขึ้นครับ"

4. เก็งคำถามที่อาจารย์มักจะถาม พร้อมแนวทางการตอบ (Q&A for Professor)
================================================================================

คำถามที่ 1: "ทำไมถึงเลือกใช้ ESP32-S3 แทนที่จะเป็น Arduino Pro Micro หรือ ESP32 ธรรมดา?"
แนวทางตอบ:
"ESP32 รุ่นดั้งเดิมไม่มีวงจรฮาร์ดแวร์ USB OTG ภายใน จึงไม่สามารถส่งสัญญาณเป็น Native USB HID แท้ๆ ได้ ต้องพึ่งพาสัญญาณบลูทูธหรือชิปภายนอก ส่วน Arduino Pro Micro ใช้ชิป 8-bit ความเร็วเพียง 16MHz และมี Flash น้อยมาก การเลือก ESP32-S3 ทำให้เราได้ทั้ง USB HID แท้ความเร็วสูง ซีพียู 32-bit Dual-Core 240MHz มี Flash 8MB และมีหน่วยความจำ NVS ในตัวสำหรับการบันทึกโปรไฟล์หลายชุดครับ"

คำถามที่ 2: "ทำไมถึงไม่ใช้ delay() ในการ Debounce สวิตช์?"
แนวทางตอบ:
"การใช้คำสั่ง delay() เป็นการเขียนโปรแกรมแบบ Blocking ซึ่งจะสั่งให้ CPU หยุดทำงานตามเวลาที่กำหนด ส่งผลให้ตัวไมโครคอนโทรลเลอร์ตรวจจับการหมุนของ Rotary Encoder พลาด หรือไม่สามารถตอบสนองต่อ USB Bus ได้ทันเวลา เราจึงใช้เทคนิค Non-blocking โดยการเปรียบเทียบผลต่างของเวลาด้วย millis() แทนครับ"

คำถามที่ 3: "Rotary Encoder ต่างจาก Potentiometer (ตัวต้านทานปรับค่าได้) อย่างไร?"
แนวทางตอบ:
"Potentiometer เป็นอุปกรณ์แอนะล็อกที่มีมุมจำกัด (มักหมุนได้ประมาณ 270-300 องศา) และใช้แรงดันไฟฟ้าแอนะล็อกบอกตำแหน่งสัมบูรณ์ ส่วน Rotary Encoder เป็นอุปกรณ์ดิจิทัลที่หมุนได้ต่อเนื่อง 360 องศาไม่จำกัดรอบ และส่งสัญญาณออกมาเป็น Digital Quadrature Pulses (Gray Code) บอกตำแหน่งสัมพัทธ์ (Relative Position) จึงเหมาะมากกับการใช้เป็นปุ่มหมุนปรับระดับเสียงหรือเลื่อนคอนเทนต์ครับ"

คำถามที่ 4: "ถ้าในอนาคตต้องการให้หมุนได้เร็วขึ้นกว่านี้โดยไม่มีสัญญาณหลุด จะปรับปรุงอย่างไร?"
แนวทางตอบ:
"สามารถปรับปรุงได้ 2 แนวทางครับ:
 1. ย้ายจากการ Polling ใน loop() ไปใช้ Hardware Interrupts (attachInterrupt) ที่ขาพิน
 2. ใช้งานโมดูลฮาร์ดแวร์ PCNT (Pulse Counter) ซึ่งเป็น Peripheral พิเศษที่มีอยู่ในชิป ESP32-S3 โดยตรง โมดูลนี้สามารถนับพัลส์ฮาร์ดแวร์ได้ในระดับฮาร์ดแวร์โดยไม่กินเวลาของ CPU หลักเลยครับ"
